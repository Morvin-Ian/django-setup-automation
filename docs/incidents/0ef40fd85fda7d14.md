# Missing cleanup step: installation files and README remain after setup, folder is not renamed to project name

## What happened

After running `./install.sh`, the user is left with a directory full of boilerplate files that are irrelevant to the new Django project — `install.sh`, `01_intro.sh`, `02_django-installation.sh`, `03_project-setup.sh`, `04_settings.sh`, `05_frontend.sh`, `README.md`, `LICENSE.txt`, `docs/`, `.gitignore`, and `.git/`. The folder itself still bears the git repo name (`django-setup-automation`) rather than the user's chosen `$projectName`. There is no mechanism to clean up these artifacts.

## Root cause

The five setup scripts (`01_intro.sh` through `05_frontend.sh`) create a Django project in the cloned repo's working directory via `django-admin startproject "$projectName" .` (note the `.` — line 32 of `03_project-setup.sh`). This places `manage.py`, the project package, and the app alongside the repository's own files. No script ever removes those repo files or renames the parent directory to match `$projectName`. The user must manually delete everything and rename the folder themselves.

## Suggested fix

Add an optional cleanup section at the end of `05_frontend.sh` (the last sourced script) that:
1. Prompts the user: *"Remove installation files and rename folder to 'projectName'? (y/N)"*
2. On `y`/`Y`, deletes `install.sh`, `01_intro.sh`–`05_frontend.sh`, `README.md`, `LICENSE.txt`, `docs/`, `.git/`, and `.gitignore`
3. Renames the current directory to `$projectName` so the final structure is clean

## Applied fix

Edited `05_frontend.sh` (at `/home/morvin/.local/share/maajun/workspaces/Morvin-Ian__django-setup-automation/05_frontend.sh`) — added 33 lines (lines 111–143) after the success banner:

- A `read -p` prompt offering the cleanup option (defaults to No).
- A conditional block that runs `rm -f` / `rm -rf` on all installation artifacts (the 6 shell scripts, README, LICENSE, docs, `.git`, `.gitignore`).
- A `cd` to the parent directory and `mv` to rename the folder to `$projectName`, then `cd` back into it, printing the final path to the user.
