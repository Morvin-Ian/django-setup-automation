# Project not installable as a package; long unwieldy name

## What happened

The user requested that this project be made installable as a Python package (like `pip install ...`), and asked for a shorter, better project name that isn't already taken on PyPI. Currently, the project is just a loose collection of bash scripts (`install.sh`, `01_intro.sh`–`05_frontend.sh`) that must be cloned and run manually — there is no `pyproject.toml` or `setup.py`, no Python package structure, and no CLI entry point. The name `django-setup-automation` is long (24 characters) and overly verbose.

## Root cause

The repository at `/home/morvin/.local/share/maajun/workspaces/Morvin-Ian__django-setup-automation` consists entirely of shell scripts with no Python packaging metadata. Specifically:

- **No `pyproject.toml` / `setup.py`** — The project has no build-system metadata, so it cannot be installed with `pip install`.
- **No Python package** — There is no `src/` or package directory with an `__init__.py`, so there are no importable modules or console-script entry points.
- **No CLI entry point** — Users must manually clone the repo, `cd` into it, and run `./install.sh`. There is no `dj-scaffold` or similar command that works from anywhere after installation.
- **The name `django-setup-automation`** is 24 characters long and contains hyphens, making it awkward to type and search for. A shorter, descriptive name (e.g. `dj-scaffold`) would be more memorable and easier to work with.

## Suggested fix

1. **Create a `pyproject.toml`** defining the project metadata and build configuration.
2. **Create a Python package** (`src/dj_scaffold/`) with:
   - `__init__.py` — version and docstring.
   - `cli.py` — a console-script entry point that orchestrates the existing bash scripts.
   - `scripts/` — bundled copies of the 5 scaffolding scripts as package data.
3. **Register the console script** (`dj-scaffold = "dj_scaffold.cli:main"`) in `pyproject.toml`.
4. **Rename the project to `dj-scaffold`** (short for "Django Scaffold") — a concise, descriptive name that is unlikely to exist on PyPI. (The user should verify availability with `pip index versions dj-scaffold` before publishing.)
5. **Update `README.md`** to document all three usage paths (pip-install, clone-and-run, editable install).
6. **Update `.gitignore`** with Python package build artifacts (`__pycache__`, `*.egg-info`, `dist/`, `build/`, etc.).
