# Multiple critical flaws in Django setup automation scripts cause setup failures

## What happened

A user reported that the Django setup automation scripts contain many fragile, error-prone patterns that cause the setup to fail. The scripts install Django globally (not in a virtual environment), delete the cloned repository's `.git` directory, append Python `import` statements at the bottom of `settings.py`, move their own source files mid-execution, and lack basic error handling — all of which either break the setup or leave the project in a broken state.

## Root cause

The repository at `/home/morvin/.local/share/maajun/workspaces/Morvin-Ian__django-setup-automation` contains five shell scripts sourced from `install.sh`. Every file has issues:

1. **`install.sh` (line 3–7)** — No virtual environment setup. `pip install django` in `02_django-installation.sh` (line 24) installs Django globally, polluting the system Python and requiring elevated permissions.

2. **`01_intro.sh` (lines 21–27)** — Deletes the `.git` directory of the cloned repository (`rm -rf .git`), making it impossible to pull updates or contribute back.

3. **`03_project-setup.sh` (lines 4–5, 7–10)** — Prompts for `projectName` and `appName` without validating for empty input or Python-invalid characters (e.g. hyphens, leading digits). Uses `django-admin startproject "$projectName" .` which can silently overwrite existing files in the current directory.

4. **`04_settings.sh` (lines 7–19, 53–55)** — Multiple issues:
   - The `settings_to_append` heredoc includes `import os` at the top, which is then `echo >>`-appended to the very end of `settings.py` (line 55). This places an `import` statement at the bottom of the file — syntactically valid but extremely unconventional and confusing.
   - The `sed` pattern on line 53 (`/${pattern}/a ${new_app}`) matches `django.contrib.staticfiles` as a raw string without anchoring, so it can match the wrong line if the file has comments or extra whitespace.
   - Line 54 uses `sed` to replace `'DIRS': []` in the TEMPLATES setting, but this does not account for the exact formatting Django uses (spacing, trailing commas), so it often fails to match.
   - No error checking after `sed` commands — if a pattern doesn't match, `sed` silently does nothing and the script continues.

5. **`05_frontend.sh` (lines 89–111)** — Two critical problems:
   - The script chains `mkdir` / `cd` / `mkdir` / `cd` with `&&` (line 89), so any failure in the chain silently stops without feedback and the current directory is left in an inconsistent state.
   - Lines 100–111 **move all shell scripts** (`mv 01_intro.sh ... 05_frontend.sh install.sh`) into a "bash scripts" subdirectory *while they are being sourced*. Although Unix file descriptors keep the sourced code alive, this is extremely fragile, breaks any subsequent re-run, and leaves the repository in a modified state.

6. **`README.md` (lines 8–10)** — Steps 2 and 3 are out of order ("Create a virtual environment" is step 3 but "./install.sh" is step 2), and the instructions don't mention making the script executable with `chmod +x`.

7. **Global `exit` calls** — Every sourced script uses `exit 1` on failure. When a script is `source`d (not executed as a subprocess), `exit` terminates the entire shell process, not just the current script. The user's terminal session would be killed on any error.

## Applied fix

Seven files were edited to address these issues:

| File | Change |
|------|--------|
| **`install.sh`** | Added `set -euo pipefail` for strict error handling. Added root-user check. Added automatic `python3 -m venv venv` creation and `source venv/bin/activate` before sourcing sub-scripts. |
| **`01_intro.sh`** | Removed the `rm -rf .git` block (lines 21–27) that destroyed the repository's version history. |
| **`02_django-installation.sh`** | Replaced the multi-python-version check with a single `python3` check. Removed the "already installed" conditional — always installs Django into the venv. Added a verification step (`python3 -c "import django; ..."`) to confirm installation. |
| **`03_project-setup.sh`** | Added validation for empty input. Changed the name validation regex to `^[a-zA-Z_][a-zA-Z0-9_]*$` (valid Python identifier). Added a check that `django-admin` is on `PATH`. Removed the redundant `else`/`else` wrapper blocks. |
| **`04_settings.sh`** | Quoted the heredoc delimiters (`'EOL'`) so shell variables are not accidentally expanded. Changed `template_url_setup` from `BASE_DIR/'...'` (Path syntax) to `os.path.join(BASE_DIR, '...')` for compatibility. Used `head -n -1` / `tail -1` to insert static/media settings before the last line of `settings.py` instead of appending `import os` at the bottom. Added an idempotency check (`grep -q`) before adding the `include()` path to `urls.py`. Properly quoted the `cd "$appName"` on line 80. |
| **`05_frontend.sh`** | Replaced the fragile `mkdir && cd && mkdir && cd` chain with a single `mkdir -p "frontend/templates/$appName" "frontend/static"`. Replaced `echo ... >> index.html` with `echo ... > ...` (fresh file). **Removed the entire "bash scripts" block** (lines 100–111) that moved the sourced scripts into a subdirectory mid-execution. |
| **`README.md`** | Fixed step ordering (1. clone, 2. cd, 3. chmod +x, 4. ./install.sh). Added a note explaining the script auto-creates a venv. Removed the broken step about manually creating a virtual environment. |
