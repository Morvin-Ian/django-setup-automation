# Stale root-level shell scripts left behind after package restructuring

## What happened

The repository was restructured from a loose collection of bash scripts into a proper Python package (`dj-scaffold`), installable via `pip`. However, the original root-level files that should have been removed as part of that restructuring are still present, creating duplication and confusion. The root directory still contains `install.sh`, `01_intro.sh`, `02_django-installation.sh`, `03_project-setup.sh`, `04_settings.sh`, and `05_frontend.sh` — even though identical copies now live inside the package at `src/dj_scaffold/scripts/`.

## Root cause

In a previous fix (commit `aa1ea82`, documented in `docs/incidents/10b283406184353c.md`), the project was converted to a Python package. The fix **created** the new package structure (`src/dj_scaffold/` with `cli.py` and bundled `scripts/`) but **did not delete** the old root-level files that it was meant to replace. This left:

- **Root-level scripts** — `01_intro.sh`, `02_django-installation.sh`, `03_project-setup.sh`, `04_settings.sh`, `05_frontend.sh` — now duplicated inside `src/dj_scaffold/scripts/`.
- **`install.sh`** — the old shell-based entry point that `source`s the root-level scripts and is now redundant with the `dj-scaffold` CLI command defined in `pyproject.toml` (line 28: `dj-scaffold = "dj_scaffold.cli:main"`).

Additionally, the `cli.py` fallback (lines 42–44) references the repo root as a script location for development, which is why the root files were kept — but this fallback should instead point to the package's own `scripts/` directory.

## Suggested fix

1. **Delete the stale root-level scripts** (these are now bundled in `src/dj_scaffold/scripts/`):
   - `01_intro.sh`
   - `02_django-installation.sh`
   - `03_project-setup.sh`
   - `04_settings.sh`
   - `05_frontend.sh`

2. **Delete `install.sh`** — it is superseded by the `dj-scaffold` CLI command.

3. **Update `src/dj_scaffold/cli.py`** to remove the repo-root fallback and always use the bundled scripts inside the package:

   **Before** (lines 37–44):
   ```python
   def main() -> None:
       # If the scripts are bundled alongside the package, run them in-place.
       bundle = _bundle_dir()
       if bundle.is_dir():
           scripts = _find_scripts(bundle)
       else:
           # Fallback: running from the repository root during development.
           repo_root = Path(__file__).resolve().parent.parent.parent
           scripts = _find_scripts(repo_root)
   ```

   **After**:
   ```python
   def main() -> None:
       """Run the bundled scaffolding scripts in sequence."""
       bundle = _bundle_dir()
       scripts = _find_scripts(bundle)
   ```

4. **Optionally update `README.md`** to remove or downplay "Option 2 — Run directly from the clone" (which references `install.sh`).

## Applied fix

*The user denied the `rm` commands to delete the stale files. The fix as described above was not applied. To complete it, run:*

```bash
rm install.sh 01_intro.sh 02_django-installation.sh 03_project-setup.sh 04_settings.sh 05_frontend.sh
```

And then edit `src/dj_scaffold/cli.py` to remove the repo-root fallback as shown above.
